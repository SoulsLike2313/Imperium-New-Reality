## 1. Особое решение текущего этапа

Текущий пакет owner foundation documents допускается прямо в Reality без WARP, потому что он фиксирует волю Owner-а и не исполняет кодовую мутацию.

Статус этих документов:

```text
OWNER_LOCKED_PROSE
VALIDATION_PENDING
```

Они не заявляют технический PASS до появления валидаторов и receipts.

## 2. Будущая стандартная политика

После этого этапа стандартный путь:

```text
Owner intent
→ Logos Prime formulation
→ WARP task/patch
→ documents/schema/matrix
→ validator
→ test
→ receipt
→ organ verdict
→ Custodes trust check
→ Throne validation
→ Owner review
→ land / fix loop / abort
```

## 3. Документы

Обычный документ не должен land-иться без валидатора, если он уже относится к технически исполняемой форме.

Foundation owner documents могут быть land-нуты direct Reality admission, но получают validation debt.

## 4. Валидаторы

Validator не должен land-иться без receipt.

Validator должен быть:

```text
script-first
strict
non-LLM-in-pipeline by default
без fake PASS
без hardcoded success
без скрытых ручных исключений
с тестируемыми fail cases
```

## 5. Receipts

Receipt должен быть зарегистрирован. PASS без receipt — fake-green.

## 6. Органные README

Органный README может быть land-нут даже если орган заполнен ниже 50%, если README честно декларирует desired form, а validator подтверждает корректность измерения actual gap.

## 7. Declared vs actual

Declared-vs-actual mismatch на ранних этапах не блокирует. Он измеряется и используется как карта развития.
