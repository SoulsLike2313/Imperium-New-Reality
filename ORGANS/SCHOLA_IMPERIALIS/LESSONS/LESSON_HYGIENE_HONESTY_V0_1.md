## Lesson learned

The system's biggest risk was not a bug. It was DRIFT between rules on paper and the actual file
tree: doctrine said "no fake green", but the repo carried 885 MB of build artifacts (79 percent),
24 unreadable BOM receipts, 129 zip, and a metric that scored 94/100 by looking only at the root.

## Turned into reusable residue (not just a summary)

- DOCTRINARIUM law: CLEAN_AND_HONEST_SYSTEM_LAW_V0_1.
- MECHANICUS tools: hygiene gate + fixers + git-truth verifier (script-first, replayable).
- INQUISITION matrix: hygiene fake-green downgrade rules.
- STRATEGIUM metric v0.2: recursive, honesty-clamped.
- ADMINISTRATUM note: receipts are NO-BOM and readers use utf-8-sig.
- CUSTODES audit: source/payload boundary checklist.

## Standing teaching

Every future task runs the hygiene gate before closure. A clean and honest system is one where the
metric, the receipts, and the file tree all tell the same story, and a script can prove it.
