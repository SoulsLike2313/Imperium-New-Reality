## I. Принципы анатомии

Империй — не граф и не дерево файлов. Это **организм**. Метафора мозга
выбрана сознательно, и она работает на нескольких уровнях:

1. **Локализация функций**. У мозга есть зоны, каждая отвечает за своё. Если
   повреждается зрительная кора — пропадает зрение, не слух. У Империума так
   же: повредился ADMINISTRATUM — система ослепла, но всё ещё знает свой
   закон (DOCTRINARIUM) и помнит свои роли (OFFICIO).

2. **Симметрия полушарий**. Левое и правое полушария мозга работают парами:
   логика ↔ паттерны, последовательность ↔ образ. У Империума каждый орган
   слева имеет **функционального двойника** справа, и они **естественно
   вызывают друг друга**.

3. **Синаптическая мембрана**. Не всё в мозге — нейроны. Сверху лежит
   полупрозрачный слой governance: шины, мембраны, write-guards. Это
   **выше нейронов**, оно их **обволакивает**, но не занимает их площадь.
   THRONE, CORE_GOVERNANCE и LOGOS_PRIME живут именно там — над корой,
   не вместо неё.

4. **Ambient / Lumen**. EMPEROR (Owner) — **не часть мозга**. Он — свет,
   падающий на мозг извне. Источник смысла, причина существования системы,
   но не её орган. Если убрать Owner-а — мозг не сломается, но **погаснет**.

5. **Локация = роль**. Расположение органа в мозге — не декоративный выбор.
   Передние доли отвечают за «осведомлённость и контроль»; затылочные —
   за «обработку входа и выработку ответа»; височные — за «накопление и
   защиту»; теменные — за «связку роли и инструмента». Эта анатомия
   **читается**, она не случайна.

## III. Левое полушарие — логика, последовательность, язык, память

### 1. ADMINISTRATUM — глаза и память Империума

**Локация**: frontal-left • **Цвет**: cyan `#4cdeeb` • **Двойник справа**: INQUISITORIUM

**Эссенция**: ADMINISTRATUM — это **сетчатка и гиппокамп** Империума одновременно.
Он **видит** весь репозиторий (структуру, файлы, sha, владельцев) и **помнит**
состояние во времени (snapshots, история, дрейф). Без него остальные органы
слепы: Inquisitorium не знает что проверять, Strategium не знает на чём строить
решения, Schola не знает на чём учиться.

**Главные функции**:
- Snapshot системы по запросу или ритму (через ASTRON)
- Карта файлов, владельцев, версий, hash-цепочек
- Хранение OWNER_PROFILE и истории взаимодействий
- Source of truth для всех визуалов (EYES рендерит из ADMIN)
- Drift detection: «что декларировано vs что есть»

**Соседи**:
- → **INQUISITORIUM** (правое frontal): отдаёт snapshot для аудита
- → **SCHOLA** (левое temporal): даёт исторические данные для обучения паттернам
- ← **ASTRONOMICAN** (левое occipital): получает тик для свежего snapshot
- ← **EVERYWHERE**: его данные — топливо для всех остальных

**Что НЕ делает**: не судит, не правит, не решает. Только видит и помнит.
Если ADMIN начал «делать выводы» — он переродился в Inquisitorium и нарушил
разделение.

### 2. OFFICIO — роли и авторизация

**Локация**: parietal-left • **Цвет**: silver `#cad8e6` • **Двойник справа**: MECHANICUS

**Эссенция**: OFFICIO — **реестр должностей** Империума. Кто кем является,
кто что может, кто кого заверяет. Без него все органы работают как «безымянные
способности», и LLM не понимает в какой роли сейчас выступает.

**Главные функции**:
- Каталог ролей: junior_inquisitor, lord_inquisitor, magos, custodian, scholar...
- Permissions matrix: какая роль что может (write_guard сверяется с этим)
- Цепочка заверения: кто кого может назначить, кто кого может снять
- Контракт «LLM сейчас в роли X» — определяет тон, ограничения, обязанности
- Эскалационные пути: junior → senior → lord → throne

**Соседи**:
- → **MECHANICUS** (правое parietal): после назначения роли — Mechanicus куёт
  инструменты под эту роль (forge cycle)
- ↔ **CUSTODES** (правое temporal): Custodes хранит permission matrix, OFFICIO
  её определяет. Один без другого не работает.
- → **DOCTRINARIUM**: каждая роль декларирована хартией

**Что НЕ делает**: не выполняет работу роли. OFFICIO — реестр, не исполнитель.

---

### 3. SCHOLA IMPERIALIS — обучение и расследование

**Локация**: temporal-left • **Цвет**: sage-bone `#c8b88a` • **Двойник справа**: CUSTODES

**Эссенция**: SCHOLA — **двойной слушатель**. Она обучает И систему, И Owner-а.
Это единственный орган, у которого **два получателя выводов**: машинный
(knowledge base для LLM, паттерны ошибок) и человеческий (дайджесты для Owner-а,
уроки в естественном языке).

SCHOLA — также **расследователь инцидентов** в составе Incident Response Triad
(CUSTODES → SCHOLA → STRATEGIUM): когда CUSTODES обнаружил брешь, SCHOLA
собирает доклад, делает выводы, готовит знание для будущего.

**Главные функции**:
- Mnemonic glyphs и язык системы — как говорить о Империуме
- Onboarding новой LLM: «прочти SCHOLA — узнаешь как работать»
- Knowledge base паттернов ошибок (что уже видели, как ловить)
- Расследование инцидентов: сбор данных, формирование выводов
- Дайджесты для Owner-а — человекочитаемые сводки
- Карьерный путь ролей (как junior_inquisitor становится lord)
- Документация для людей (если появятся коллабораторы)

**Соседи**:
- ← **CUSTODES**: получает сигнал об инциденте
- ↔ **STRATEGIUM**: совместно вырабатывает путь решения; SCHOLA сохраняет
  знание, STRATEGIUM сохраняет механизм
- → **ADMINISTRATUM**: использует исторические snapshot-ы для паттерн-анализа
- → **OWNER** (Lumen): человекочитаемые дайджесты идут наверх

**Что НЕ делает**: не охраняет (это CUSTODES), не принимает финальных решений
(это STRATEGIUM), не судит подозреваемых (это INQUISITORIUM).

### 4. ASTRONOMICAN — ритм и сигнал

**Локация**: occipital-left • **Цвет**: violet `#a866ff` • **Двойник справа**: STRATEGIUM

**Эссенция**: ASTRONOMICAN — **метроном** Империума. Если все остальные органы
«реактивны» (срабатывают на запрос), то ASTRONOMICAN — **проактивен**: он
бьёт по часам, и его удар запускает каскад действий. Без него система
молчит до запроса; с ним — живёт собственной жизнью.

**Главные функции**:
- Тики (heartbeat) — каждые N минут, часов, дней
- Расписание периодических проверок (Inquisitorium sentinels по графику)
- Расписание snapshot-ов (Administratum сохраняет состояние)
- Расписание дайджестов (Schola собирает уроки за период)
- Сигналы об особых датах (релизы, ревью, итерации)
- Долгие циклы: ежедневный / еженедельный / месячный пульс

**Соседи**:
- → **ADMINISTRATUM**: «сделай свежий snapshot»
- → **INQUISITORIUM**: «запусти плановую проверку»
- → **STRATEGIUM**: «время принимать решение по KPI»
- → **SCHOLA**: «время собрать дайджест»

**Что НЕ делает**: не выполняет сами действия. Только бьёт в колокол —
кто услышал, тот делает.

## IV. Правое полушарие — паттерны, защита, инструменты, решения

### 5. INQUISITORIUM — надзор и адверсариальный аудит

**Локация**: frontal-right • **Цвет**: blood-red `#ff3b5c` • **Двойник слева**: ADMINISTRATUM

**Эссенция**: INQUISITORIUM — **внутренний враг системы по должности**. Он *обязан
подозревать*. Если ADMINISTRATUM смотрит на мир и говорит «вот что есть»,
INQUISITORIUM смотрит на то же самое и говорит «а правда ли это? а не подделано?
а не пропущено ли что-то?». Это адверсариальная пара, и именно это разделение
делает Империум антихрупким.

INQUISITORIUM не доверяет никому — включая DOCTRINARIUM. Если Doctrinarium —
конституция, то Inquisitorium — Прокуратура, которая проверяет соблюдение
конституции даже самим её хранителем. Это последний рубеж против fake-green.

**Главные функции**:
- Адверсариальный аудит каждого пака перед landing (E3)
- Sentinel-тесты против fake-green симуляций
- Триггер Schola при подозрениях на pattern-deviation
- Kernel pollution detection — главная защита master-ветки
- Внеплановые проверки при сигнале CUSTODES или ADMIN-drift
- Cross-check между organ charters и реальным состоянием

**Соседи**:
- ← **ADMINISTRATUM**: получает snapshot — что есть
- ← **DOCTRINARIUM**: сверяется с каноном — что должно быть
- → **SCHOLA**: эскалирует подозрительный паттерн на расследование
- → **CUSTODES**: эскалирует permission-breach (если нашёл проникновение)

**Что НЕ делает**: не охраняет (это CUSTODES), не пишет законы (это DOCTRINARIUM),
не исполняет приговор (нет приговора — есть verdict «pass/fail» и отчёт).
INQUISITORIUM — **прокурор**, не судья и не палач.

### 6. MECHANICUS — кузница инструментов

**Локация**: parietal-right • **Цвет**: forge-orange `#ff7a1f` • **Двойник слева**: OFFICIO

**Эссенция**: MECHANICUS — **орган, который делает делание возможным**. Все остальные
органы *знают*, *видят*, *судят*, *решают* — но без инструментов это разговоры.
MECHANICUS отвечает на вопрос «чем именно?». Если OFFICIO выдал роль «junior
inquisitor», MECHANICUS кует **sentinel-скрипт** под эту роль. Если STRATEGIUM
решил «нужна метрика KPD», MECHANICUS строит **измерительный инструмент**.

Это также **анти-галлюцинаторный** орган: пока инструмент не выкован и не
валидирован, LLM **не имеет права** «делать вид» что выполняет задачу.
MECHANICUS — гарант того, что система оперирует **реальными артефактами**, а не
их описаниями.

**Главные функции**:
- Кузница: STAGE_1/2/3 ops, e3_runner, sentinels, gates
- Forge cycle: «роль выдана → инструмент скован» (вместе с OFFICIO)
- Ремонт: hot-patches, идемпотентные fixes
- Каталог готовых артефактов (никаких изобретений велосипеда)
- Templates для новых паков (DOCTR-*, ADMIN-*, INQ-* skeletons)
- Toolchain validation: каждый инструмент проходит E3 перед попаданием в репо

**Соседи**:
- ← **OFFICIO**: «нужен инструмент для роли X»
- ← **STRATEGIUM**: «нужна метрика Y»
- → **DOCTRINARIUM**: каждый инструмент подчинён хартии
- → **INQUISITORIUM**: каждый инструмент проходит адверсариальный аудит

**Что НЕ делает**: не назначает роли (OFFICIO), не решает что нужно (STRATEGIUM),
не санкционирует использование (CUSTODES). MECHANICUS — **поставщик**, не
заказчик и не пользователь.

### 7. CUSTODES — защита Императора и Трона

**Локация**: temporal-right • **Цвет**: imperial-gold-red `#c8551f` • **Двойник слева**: SCHOLA IMPERIALIS

**Эссенция**: CUSTODES — **личная гвардия Императора в системном смысле**. Это
не «ещё один аудитор» — CUSTODES хранит **матрицы допусков**, **пороги**, **окна
разрешённого**, и **реагирует на бреши**. Это **активная** защита, не пассивное
наблюдение.

Отличие от INQUISITORIUM критично:
- INQ спрашивает «**это правда хорошо?**» (адверсариальный аудит качества)
- CUSTODES спрашивает «**это разрешено?**» (permission gate, access control)

INQ может пропустить технически корректное действие, которое **не должно**
совершаться этим актором. CUSTODES — наоборот: он не оценивает качество, он
оценивает **право**. Двойная защита: INQ ловит фейк, CUSTODES ловит превышение
полномочий.

CUSTODES — также **первое звено Incident Response Triad**. Когда он фиксирует
брешь — он не расследует сам (это не его роль), он **зовёт SCHOLA**, и та с
STRATEGIUM-ом вырабатывают ответ.

**Главные функции**:
- Матрицы допусков: что какая роль может, в какое время, на каком объекте
- Пороги и окна: лимиты на write, на merge, на cascade depth
- Breach detection: фиксация попыток превышения
- Эскорт критических операций (merge в master, активация SEAL)
- Триггер Incident Response Triad при бреши
- Hardened параметры для 100% защиты от лишнего действия

**Соседи**:
- ↔ **OFFICIO**: OFFICIO определяет роли, CUSTODES хранит permissions этих ролей
- → **SCHOLA**: «брешь зафиксирована, расследуй»
- → **STRATEGIUM**: «нужна выработка нового защитного механизма»
- → **THRONE**: эскорт до самой Печати

**Что НЕ делает**: не расследует (SCHOLA), не выносит вердикт о качестве (INQ),
не принимает финального решения (STRATEGIUM). CUSTODES — **щит и сторож**, не
детектив и не судья.

---

### 8. STRATEGIUM — KPI, решения, память механизмов

**Локация**: occipital-right • **Цвет**: emerald `#3edb9c` • **Двойник слева**: ASTRONOMICAN

**Эссенция**: STRATEGIUM — **военный совет Империума**. Он отвечает на самый
трудный вопрос — «**куда двигаться дальше?**». KPI, приоритеты, выбор курса,
арбитраж между конфликтующими предложениями органов. Если ASTRON говорит «время
принять решение», STRATEGIUM это решение **выдаёт**.

Ключевая особенность v0.2 — STRATEGIUM **помнит не только решения, но и
механизмы их выработки**. Это decision-pattern cache: когда возникает похожая
ситуация, STRATEGIUM **переиспользует** механизм, а не выводит его заново. Это
**вычислительная экономия** для всей системы и **последовательность** для
Owner-а.

STRATEGIUM — также **второе звено Incident Response Triad** (после SCHOLA):
когда SCHOLA подготовила доклад об инциденте, STRATEGIUM выбирает путь решения
и **фиксирует механизм** в кэше.

**Главные функции**:
- KPI / KPD системы (метрики производительности и качества)
- Roadmap: какие паки следующие, в каком порядке
- Арбитраж конфликтов между органами
- Decision-pattern cache: «как мы решали похожее раньше»
- Выработка специфического ответа на инцидент (с SCHOLA)
- Стратегические разрезы: что важно сейчас, что отложить

**Соседи**:
- ← **ASTRONOMICAN**: метроном «время решать»
- ← **ADMINISTRATUM**: данные для решения
- ↔ **SCHOLA**: совместная выработка ответа на инциденты
- → **OFFICIO**: «выдай роль под новую задачу»
- → **MECHANICUS**: «нужен инструмент для исполнения решения»

**Что НЕ делает**: не собирает данные (ADMIN), не расследует инциденты (SCHOLA),
не исполняет (MECH). STRATEGIUM — **штаб**, не разведка и не войска.

## V. Мозжечок — рефлекс закона

### 9. DOCTRINARIUM — канон Империума

**Локация**: cerebellum (задне-нижняя часть мозга) • **Цвет**: doctrinarium-gold `#ffcc44` • **Двойников нет — это фундамент**

**Эссенция**: DOCTRINARIUM — **то, что не обсуждается**. В биологическом мозжечке
живут заученные движения — ходьба, равновесие, реакции. Они не проходят через
кору, не требуют сознательного решения. Они **есть**, и они **срабатывают**.

DOCTRINARIUM — то же самое для Империума. Здесь живут **законы, хартии,
тракты, политическая форма системы**. Когда LLM хочет сделать действие, ей не
нужно «думать» — DOCTRINARIUM **уже** сказал что нельзя. Это рефлекс, а не
деберация.

DOCTRINARIUM — **organ-owner этого самого документа**. Анатомия — часть канона.

## VI. Синаптическая мембрана — governance поверх коры

Это три слоя, **лежащих выше нейронов**. Они не занимают площадь органов — они
**обволакивают** мозг как полупрозрачная мембрана, через которую всё течёт. В
визуале EYES это будет отдельный слой (gloss-overlay) поверх 9 органов.

### 10. _CORE_GOVERNANCE — шины, write_guard, kernel container

**Локация**: весь мозг (мембрана) • **Цвет**: bone `#e8e2d0`

**Эссенция**: Это **невидимая ткань Империума**. Она не выполняет функции
органов, но без неё органы не могут работать. _CORE — это: шины
passed-message-bus, write_guard (кто может писать в master), ratchets (однонаправленная
история), identity signatures, provenance schema, kernel container.

**Главные функции**:
- write_guard: принимает или отклоняет merge в master
- Provenance schema: все паки имеют PROVENANCE.json одинаковой формы
- Identity signatures: каждый артефакт подписан и проверяем
- Ratchets: master движется только вперёд, никогда назад
- Aggregate hashing: детерминированные хэши паков
- Kernel container: физическая оболочка репозитория

**Почему это мембрана, а не орган**: орган имеет функцию («вижу», «кую», «решаю»).
_CORE не «делает» ничего — он **делает возможным делание** органами, пропуская
одно и блокируя другое.

### 12. LOGOS_PRIME — LLM-присутствие, мост полушарий

**Почему он в governance, а не орган**: LOGOS_PRIME не «выполняет функцию» — он
**есть** факт присутствия. Он не «орган мышления» — он **само мышление в процессе**.
Этому место на мембране, не в ткани.

## VIII. Симметрия полушарий — 4×2 пары

Каждый орган слева имеет функциональную пару справа. Это **вызывающая пара** —
один естественно зовёт другого в рабочем потоке.

| Пояс | Левое (логика/язык) | Правое (паттерн/защита) | Смысл пары |
|------|--------------------|----------------------|--------------|
| Frontal | ADMINISTRATUM (вижу) | INQUISITORIUM (сужу) | «осведомлённость» → «подозрение» |
| Parietal | OFFICIO (кто) | MECHANICUS (чем) | «роль» → «инструмент под неё» |
| Temporal | SCHOLA (учу) | CUSTODES (защищаю) | «как растут» ↔ «как охраняются» |
| Occipital | ASTRONOMICAN (когда) | STRATEGIUM (куда) | «время» → «выбор» |
| Cerebellum | DOCTRINARIUM — общий фундамент (пары нет) | | |

## IX. Inter-organ flows — именованные паттерны

Это **первоклассные конструкции системы**. Каждый поток имеет имя, он ожидаем и
вызывается явно во всех future-паках.

### 1. Incident Response Triad («Иммунный ответ»)

```
CUSTODES (обнаружил брешь)
  ↓ инцидент
→ SCHOLA (расследует, пишет доклад)
  ↔ STRATEGIUM (вырабатывает механизм, запоминает)
  ↓ результат
  ├ SCHOLA → knowledge base (паттерн для системы)
  ├ SCHOLA → Owner digest (урок для Uttkarsh)
  └ STRATEGIUM → decision-pattern cache
```

Аналог: биологический иммунный ответ (барьер → анализ антигена →
выработка специфического антитела + память). Диагональ в мозге:
temporal-right → corpus callosum (LOGOS_PRIME) → temporal-left → occipital-right.

### 2. Discovery Loop

```
ADMINISTRATUM (snapshot «вот что есть»)
  → INQUISITORIUM («а это правда? а это не фейк?»)
  → verdict pass/fail
```

Пара frontal-долей: «вижу» встречает «подозреваю».

### 3. Forge Cycle

```
OFFICIO («нужна роль X»)
  → MECHANICUS («ковать инструмент под X»)
  → DOCTRINARIUM («хартия роли X зафиксирована»)
  → CUSTODES («permissions роли X внесены в матрицу»)
```

Пара parietal-долей + закрепление в каноне и защите.

### 4. Tempo Decision

```
ASTRONOMICAN («тик — время решать»)
  → STRATEGIUM (оценка KPI, выбор курса)
  → OFFICIO + MECHANICUS (исполнение)
```

Пара occipital-долей: «когда» запускает «куда».

### 5. Canon Anchor

```
DOCTRINARIUM (канон)
  ↔ любой орган при любом действии (рефлекс закона)
```

Мозжечок как фундамент — все органы «наступают» на него при каждом движении.

## XI. Чего в Империуме НЕТ (negative space)

Это список существен, потому что определение «чего нет» ровно важное определения
«что есть».

- **Нет chaos-органа**. Нет зоны, в которой легитимно работать вне хартий.
  Бросовые и сырые идеи живут в внешних sandbox-ах, не в организме.
- **Нет ego-органа**. Ни один орган не «хочет» и не «борется за выживание». Всё
  «хотение» живёт в EMPEROR.
- **Нет generative-органа**. Система не «придумывает» новые зоны. Новые
  органы рождаются только через EMPEROR и хартию DOCTRINARIUM-а.
- **Нет «generic LLM»-слота**. Любая LLM, вошедшая в систему, становится
  LOGOS_PRIME — первоклассным объектом с обязанностями. Не «вызываемым
  сервисом».
- **Нет «безымянных действий»**. Каждое действие имеет actor (role из OFFICIO) +
  warrant (permission из CUSTODES) + signature (из _CORE).
- **Нет master-изменений вне STAGE 1–2–3**. Не бывает «я быстро внёс fix» —
  любое изменение проходит warp → E3 → squash-merge.
